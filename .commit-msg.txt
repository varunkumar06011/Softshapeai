fix: use backend unitCost for AC consumption recalculation

The frontend was recalculating consumption as sale × purchaseCost,
which is wrong for spirits (30ml peg-based items). For spirits, Sale
is in pegs and the cost-per-peg is much smaller than the bottle cost.

Now uses the backend-provided unitCost field:
- Spirits: unitCost = purchaseCost × 30 / effectiveBottleSize
- Beer/other: unitCost = purchaseCost

When the user edits purchaseCost, unitCost is scaled proportionally
from the backend's base unitCost/base purchaseCost ratio.

This fixes the inflated consumption values and negative profits that
occurred when editing spirit items (e.g., BLEDERSPRIDE, ROYAL STAG,
SIGNATURE, etc.).
